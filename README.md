# RealRain XP12

Replaces X-Plane 12's "hyperspace" rain streaks with realistic windshield rain:
individual droplets, trails and merging, movement driven by airspeed, wind and
gravity, density synced to X-Plane weather, and adjustable quality.

## Current stage: prototype diagnostics

Before building the droplet renderer, version 0.1 answers three questions inside the sim:

| Question | Tool in the plugin |
|---|---|
| Which weather/flight datarefs exist, and what do they read? | **Debug window** (live values; missing datarefs shown in red) |
| Can the built-in rain streaks be turned off? | **Scan rain datarefs** (logs candidates to `Log.txt`) + `probe` / `override` lines in `RealRain.ini` + **Apply streak overrides** |
| Can we draw geometry fixed to the airframe under Vulkan? | **Windshield test quad** (translucent blue rectangle in front of the pilot) |

All of these are under **Plugins > RealRain** in X-Plane.

## Layout

```
CMakeLists.txt          build (outputs the XP12 "fat plugin" folder)
config/RealRain.ini     default settings (embedded; written on first run)
config/skunkcrafts_updater.cfg.in   updater config template
release/RealRain/       SkunkCrafts Updater depot (generated by make_release.ps1)
src/
  main.cpp              plugin entry points, menu, flight loop
  SimData.*             dataref lookup (with XP11 fallbacks) and per-frame reads
  DebugWindow.*         on-screen diagnostics window
  StreakControl.*       force/restore datarefs listed as overrides
  DatarefScan.*         search all registered datarefs by name (XPLM 4.0 API)
  TestQuad.*            airframe-locked draw test (xplm_Phase_Modern3D)
  Config.*, Log.*       ini parsing, Log.txt output
scripts/
  get_sdk.ps1           download the X-Plane SDK into third_party/XPSDK
  install.ps1           copy the build into X-Plane 12's plugins folder
  make_release.ps1      build and refresh the SkunkCrafts depot
```

## Building (Windows)

Needs Visual Studio 2022 (or Build Tools) with the C++ workload, CMake 3.21+, and the X-Plane SDK 4.x.

```powershell
.\scripts\get_sdk.ps1
```

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
```

```powershell
cmake --build build --config Release
```

```powershell
.\scripts\install.ps1
```

The plugin lands in `<X-Plane 12>/Resources/plugins/RealRain/win_x64/RealRain.xpl`.
Messages are written to `<X-Plane 12>/Log.txt` with the prefix `RealRain:`.
`install.ps1` never touches your `RealRain.ini`.

## Testing the prototype in the sim

1. Load a flight with rain (Weather > set precipitation), sit in the cockpit.
2. Check the debug window: precipitation, airspeed, wind and OAT should be live, none red.
3. **Plugins > RealRain > Scan rain datarefs to Log.txt** and read the `RealRain: scan:` lines.
4. Add promising names as `probe = ...` lines, reload, and watch them change with the weather.
5. Add writable candidates as `override <name> = 0` and toggle **Apply streak overrides**;
   see whether the streaks outside disappear. Overrides are always restored when the
   plugin is disabled.
6. Turn on **Windshield test quad**. It should stay fixed in front of you while you fly,
   bank and pan the view. Adjust `test_quad_offset_*` to place it on the glass.

## Updates via SkunkCrafts Updater

Installed copies carry `skunkcrafts_updater.cfg`, so
SkunkCrafts Updater (available on X-Plane.org) keeps RealRain up to date from this repository's depot folder,
[`release/RealRain`](release/RealRain). Your `RealRain.ini` is blacklisted: updates never
replace it, and the plugin writes a default one if it's missing.

To publish an update:

1. Bump the version in `CMakeLists.txt` (`project(RealRain VERSION x.y.z ...)`).
2. Run `.\scripts\make_release.ps1`. It builds, copies the plugin into `release/RealRain`,
   and rewrites the updater's cfg, whitelist (CRC32) and sizes list.
3. Commit and push. Users' updaters see the new version on their next check.
